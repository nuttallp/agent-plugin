## Starting from “I want to make good MetaLog content”

Do not ask the user to write a script. First read linked `get_profile`, relevant `list_memory`, `list_assets` and actual `browse_styles`. These establish rights, known taste, owned material and ready options; an account profile is not automatically a product description. Reuse verified MetaLog facts. If its audience/product purpose remains unknown, ask one focused question: “What is the main thing MetaLog helps people do, and who is it for?” Meanwhile inspect suitable Clypmint clone previews/narrator auditions and propose a first format.

A worked reply: “I'll develop the first concept and script. I'd start with one clear thing MetaLog helps someone do, shown in a 30-second vertical explanation. Bold Navy Statement gives it readable type and a calm voice; I'll show its Clypmint preview plus Chris and Sarah auditions. If you have a logo or useful product screen, add them through the available upload surface once. Otherwise I'll make a deliberate text-led first draft. What is the main thing MetaLog helps people do, and who is it for?” Omit the question when context answers it. Do not halt an asset-free idea or ask a series of brand questions.

Suppose the user's answer establishes only these facts: “MetaLog is a personal nutrition log. People record meals and notes.” Propose a concrete first concept, **One simple entry**, and draft these exact words:

> One meal is a moment. A few notes can make it easier to remember. MetaLog is a personal nutrition log for recording meals and notes. Start with what you ate, add what you want to remember, and keep the next entry simple.

The script uses those stipulated facts, not assumed health outcomes or undocumented app features. Match it to readable “meal → note → next entry” beats; use a real supplied screen if available, otherwise honest type/diagrams instead of fake product UI. The user did not need to prewrite it. Show exact narration when facts need confirmation or script approval was requested. When facts and draft authorization are established, proceed; do not add another approval loop to every reversible decision.

Recommend a real logo/product screen or relevant owned clip when it enhances the film, and request missing media once through actual transport: `import_asset` for a supported image/audio descriptor, existing assets from `list_assets`, the returned Brand page when needed, or footage upload when editing the user's video. Public image URLs are not accepted by the current import tool. Idea-to-video still needs no footage or brand files. Retain the ready style ID/version, narrator, exact words/asset decisions and stable operation ID, then show the actual version.

## When an exact script, logo and named portrait are requested

Suppose the user requests a 30-second vertical MetaLog explainer about Ray Peat, supplies approved exact narration, wants their actual logo and an identified portrait, and has not asked to post. This is an operating example, not new medical content or a product-capability claim. Use their approved text/sources; do not supply thyroid/seed-oil/metabolic claims from memory, turn an attributed idea into a treatment promise, or invent a product story.

1. **Reuse the brief.** “I'll keep your narration exactly, make this faceless with your actual MetaLog logo and the approved portrait, and show the result.” Resolve an unsourced factual/health sentence before treating it as approved; do not silently rewrite an approved script. Read `get_profile`, relevant `list_memory` and `list_assets`. Record logo/portrait/product roles with actual IDs. Check portrait identity; an unrelated scientist or book cover is not a substitute.
2. **Choose the actual available look.** For this narrated explainer call `browse_styles` and consider ready Bold Navy Statement with its real preview/returned ID; its extracted narrator default is Chris. Show Sarah/Alice auditions for a calmer explanation when undecided, or retain the user's choice. Serif Editorial Launch is a different type/music motion treatment with `inputs.voice: none`; offer it only if the user wants that non-narrated direction. If unavailable, show another suitable returned narrated style. Use actual IDs/versions and never transfer a private copy ID between accounts.
3. **Gather the exact assets.** Reuse owned logo/portrait IDs from `list_assets`. When the host provides a supported OpenAI file descriptor, call `import_asset` with that `file` and a stable `operation_id`, then retain its `asset_staging_key`. Other hosts use the returned Studio Brand/upload fallback once; a public logo link alone does not make the current import tool usable. Keep sources/roles and never substitute a public bucket or another person's image.
